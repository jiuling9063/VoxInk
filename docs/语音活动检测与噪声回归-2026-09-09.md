# 语音活动检测与噪声回归

日期：2026-09-09。状态：开发回归通过，A3 部分通过；正式环境噪声、真实轻声和跨系统验收尚未完成。

## 问题与结果

上一批无提示 ASR 会把固定低音量合成噪声识别为“嗯。”。本批在 ASR 前加入系统自带 SoundAnalysis 整段语音检测：该文件在最终 App 中被拦截，结果为空、复制不可用，提示“没有检测到清晰语音，未写入文字。可重试或删除本次录音。”。重试后仍不产生文字，也不误报识别成功。

随后导入 SMOKE-003，模型重新加载并输出完整的中英混合简体结果。导入仅展示结果，没有粘贴或发送消息；两次测试保留音频均已通过界面删除，恢复目录为空。用户此前确认的计数 6→7、完整恢复通过，保留为原构建单次实体输入证据，不移记到本批重新签名构建。

## 实现边界

- 使用 `SNClassifySoundRequest(.version1)`，读取 `speech` / `whispering` 置信度；任意窗口最大值达到 0.5 即保留整段进行 ASR。阈值不是响度门槛。
- 窗口 0.5 秒，重叠 50%；只向分类器末尾补 8000 个零采样，覆盖不足一个窗口的尾音。原文件不修改、不裁剪，ASR 仍读取完整原音频。
- 校验 16kHz、单声道、有限采样、时长不超过 60 秒；后台分析并传播取消。没有结果、分类器不可用或分析失败均返回显式错误，不冒充静音结论。
- 数字全零仍直接拦截。分类器判定没有清晰语音时，保留本次录音供重试/删除，沿用最多一条、最长 24 小时的私有恢复存储。
- 识别返回值区分丢弃、仅音频、音频和文字，避免把旧结果关联到新拒绝录音；复制旧文字不会误删新录音。
- 重试释放常驻模型后立即同步“尚未加载”。分类器拦截不再留下错误的“模型已加载”状态，检测错误也不误标为模型损坏。
- 使用系统内置分类器，无新增模型下载或音频上传。产品仍不启用 ASR 热词提示，不能把这批检测通过当作热词质量门通过。

Apple 技术依据：[SoundAnalysis](https://developer.apple.com/documentation/SoundAnalysis)、[系统声音分类介绍](https://developer-mdn.apple.com/videos/play/wwdc2021/10036/)。实际 API 与窗口约束同时核对本机 SDK。
