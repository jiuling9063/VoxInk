## 已实现的规则边界

固定顺序为：提取原文保护片段 → 未保护文字的控制字符/Unicode/空白整理 → 固定 OpenCC 配置 → 标点和受限填充词整理 → 原样拼回保护片段。没有使用可能与用户输入碰撞的占位符。

1. 保护代码围栏、反引号内代码、URL、邮箱、绝对/相对路径及带引号路径、版本号、ASCII 标识符与带下划线混合标识符、数字/金额/日期/时间。带千位空格的数字和货币符号后的空格也按原文保留。未声称能从任意无标记自然语言中完整解析所有编程语言。
2. 未保护文字使用 NFC，不做可能改变全角数字等内容的兼容折叠。去除无效控制字符和明确的不可见格式字符，保留换行、Emoji/文字所需连接符与变体选择符。
3. 合并异常横向空格、中文之间的多余空格，保留英文词间分隔和保护片段内部空白；统一未保护的换行，最多保留一个空白段落。中文异常空格在 OpenCC 前处理，使“軟  體”仍能得到“软件”。
4. 合并明显重复的逗号、分号、冒号和两个中文句号；保留省略号、重复问叹号和混合问叹语气。保护片段之间的重复标点不改，避免把 `1,,234` 整理成看似另一个金额的 `1,234`。
5. 仅在句首“呃/呃呃 + 逗号”之后出现已知句子开头时清理：请、我想、我先、我们、这次、现在、今天、明天、接下来。单独回应、句中“呃”、讨论这个字的句子，以及“嗯”“就是”“这个”“然后”等有潜在含义的词保留。其余情况不猜测置信度。
6. 原始 ASR 字符串只读保留。用户始终可展开原文；原文与结果相同会明确说明无需调整。
7. OpenCC 不可用时仍沿用字符级降级及提示；完全转换失败返回原文。空结果检查只用于判断，不再二次裁剪受保护内容。

以下是固定开发样例，不是人工验收语料：

| 输入 | 结果/保护方式 |
| --- | --- |
| `呃，請用Swift整理  檔案，，` | `请用Swift整理文件，` |
| `Swift開發軟體` | `Swift开发软件`，中文不再被吞入 ASCII 标识符保护范围 |
| `檔案和文件夾中的文件。` | `文件和文件夹中的文件。`，再次处理不漂移 |
| `嗯，是的。` / `呃，是语气词。` | 保留 |
| `¥  12,345.60` / `1  234  567` / `2026 年  9 月 9 日` | 内部格式原样保留 |
| `1,,234` / `0::30` / `真的吗？？` / `Wait...` | 不猜测数字含义或抹去语气 |
| 反引号、代码围栏、带空格引号路径 | 内容逐字保留 |

尚未实现：用户词典、基于真实停顿信息补标点、可选 LLM 润色。当前 ASR 合同只有整段文字，不能据此捏造停顿时间或断句置信度。规则在固定开发样例通过，不代表 20 条口语原意门槛或全部正式语料通过。

## 发现的问题与修复

- 旧保护表达式把英文字母后所有中文都吞入标识符，导致 `Swift開發軟體` 不转简体。改为明确的 ASCII 标识符边界，混合下划线标识符及有标记代码继续保护。
- 固定 OpenCC `twp → cn` 词库存在“檔案 → 文件”和“文件 → 文档”的两步映射。转换前保护已正确的大陆名词“文件”，保持原有“檔案 → 文件”预期，并锁定二次处理样例。
- 原文入口最初仅在文字有变化时显示，与设置中的说明不一致。改为始终可展开；无需调整时给出明确提示。
- 引导较长时结果位于可视区域外。新结果或恢复录音出现后滚动到处理状态区；展开原文后根据实际布局高度滚动，避免依赖固定延时。
- 实测发现同一路径有两个 VoxInk 进程。启动脚本使用的 `open -n` 会请求新实例；改为普通启动，打包加入 `LSMultipleInstancesProhibited`，验证脚本只在当前路径恰好一个进程时通过。该声明参考 [Apple 的 Launch Services 说明](https://developer.apple.com/library/archive/documentation/General/Reference/InfoPlistKeyReference/Articles/LaunchServicesKeys.html)。最终构建的重复启动请求实测未产生第二进程。
