# 语落商店版功能方案（待确认）

2026-09-22。此文件是可审阅的产品边界方案，不代表已经实现、发布或得到审核批准。现有 0.1.10 直装版保持完整功能。

## 本次核查结论

InputMethodKit 能用于开发 macOS 输入法，但不能据此推导商店分发可行。[Apple DTS 的答复及 2026 年 4 月后续说明](https://developer.apple.com/forums/thread/134115)排除了当前通过 Mac App Store 分发这类输入法的路线。因此不再为上架目的构建或安装输入法原型。

## 推荐：同一套核心，两个发行渠道

| 能力 | 公证直装版 | 拟议商店版 |
| --- | --- | --- |
| 本地录音、识别、文字整理和润色 | 保留 | 保留 |
| 五种界面语言、语音语言选择 | 保留 | 保留 |
| 纠正词库、导入、预览 | 保留 | 保留；通过系统文件选择器授权 |
| 首次模型下载、内置运行环境 | 保留 | 保留；迁到正式沙盒下载服务和容器存储 |
| App 内工作台、原文和结果、明确复制按钮 | 保留 | 作为主要工作流 |
| 全局快捷键及 HUD | 保留当前行为 | 可研究用于启动录音或唤起工作台；实体事件和后台权限验证通过后才承诺，不默认承诺按住/松开等价体验 |
| 自动写入任意前台应用、远程工具模拟粘贴 | 保留当前能力范围 | 不承诺；首版采用用户明确复制后自行粘贴 |
| 系统服务 | 可选 | 可选补充；只在支持的目标应用提供，不能替代主要工作流 |

用户可见的变化：商店版把“说完自动进入目标输入框”改为“在工作台得到结果 → 点击复制 → 回到目标处粘贴”。这是实质体验差异，必须在选择前明确，不用同一套宣传暗示两个版本能力完全一致。

商店版能独立完成录音到文本结果，不要求安装直装版、额外输入法或站外 helper。首次使用仍只需系统权限和模型下载，不让用户配置 Python。该设计减少当前已知架构冲突，但最终仍需完整构建与 App Review。

## 确认后实施顺序

1. 增加明确的发行配置与输入输出能力边界，分别控制初始化路径和界面。商店构建不启动 AX 查询、模拟粘贴或全局事件 tap；直装构建的现有链路保持回归测试。
2. 将下载放入独立 XPC 服务，主 App 和推理 helper 保持离线；完成真实权重的流式下载、续传、取消、验证、崩溃恢复和签名。
3. 迁移模型、词典和恢复文件至沙盒容器。旧目录通过用户选择授权导入；处理只读、权限失效、空间不足和升级中断。
4. 打通 App 内录音 → 识别 → 润色 → 结果 → 复制，完整处理权限拒绝、无模型、超时、取消和失败恢复。系统服务另行验证长时间处理及目标变化，未通过则不纳入首发承诺。
5. 完成商店分发签名和 App Store Connect 配置、稳定系统/第二台 Mac 测试、隐私政策和截图，再执行上传及 TestFlight 验证。

工程上可以共用识别、润色、词典和界面主体；不能仅隐藏设置项而继续在商店构建里运行受限路径。版本标识和数据位置需独立规划，避免两个渠道同时运行时抢占快捷键或损坏数据。

## 其他选择

- **完整体验优先，暂缓商店**：继续完善并公证直装版，不承诺上架时间。
- **先获得 Apple 针对现有交互的技术建议**：使用已更新但未发送的 `docs/apple-dts-cross-app-input.md`，只咨询公开 API 方案；不能将技术支持答复视为审核预批准。

待确认的只有产品边界：是否接受一个独立可用、以显式复制为主要输出方式的商店版。没有替用户做这个选择，也没有削减当前产品功能。
