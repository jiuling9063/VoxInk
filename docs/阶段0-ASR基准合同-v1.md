# 阶段 0：ASR 基准合同 v1

- 合同版本：v1.1
- 日期：2026-09-08
- 状态：`CONTRACT_READY / READY_FOR_SMOKE_DOWNLOAD`
- 目的：在查看正式测试结果前冻结测试方法，避免按结果调整口径。

## 1. 范围与退出条件

本合同约束阶段 0 的无界面本地 ASR benchmark 子项，不在该子项中开发菜单栏、快捷键、产品自动粘贴、智能润色或安装包。固定文字的网易 UU 粘贴与剪贴板事务可以作为独立实验并行开展；ASR 候选还必须用最小独立进程 Worker 验证加载、取消、断连和重启，但不在本阶段实现完整产品 XPC 服务。

候选范围固定为：

1. Qwen3-ASR 0.6B 4-bit MLX；
2. WhisperKit Large V3 Turbo；
3. WhisperKit Medium。

阶段退出条件：三套候选在同一设备、同一语料和同一统计口径下完成测试，所有原始结果可追溯，并形成唯一默认 ASR 的 ADR。未通过硬门槛时不得用综合得分掩盖失败；如果全部失败，应输出 `NO_MODEL_SELECTED`。在此之前，为小样、Worker 或产品闭环接入的模型一律标记为临时候选。

## 2. 模型清单闸门

运行 benchmark 前必须建立 `benchmark/model-manifest.json`。每个候选必须填写：

```json
{
  "engine": "candidate-name",
  "engine_version": "exact-version",
  "source_url": "verified-source",
  "source_revision": "immutable-commit-or-tag",
  "model_id": "exact-model-id",
  "model_revision": "immutable-revision",
  "license": "verified-license",
  "files": [
    {
      "name": "model-file",
      "bytes": 0,
      "sha256": "lowercase-hex"
    }
  ]
}
```

禁止填写 `latest`、浮动分支或运行时猜测的下载地址。当前 `benchmark/model-manifest.json` 已记录候选的不可变源码 revision、模型 revision 与清单 SHA-256，状态为 `ready_for_smoke_download`（个别候选含设备限定状态）。该状态只表示已有下载前元数据，不表示模型文件已下载并逐文件复核，也不表示任何候选已在本机成功加载或完成转录。此前“等待网络恢复补齐不可变元数据”的阻塞结论已过期。

Qwen 当前上游 `fromPretrained` 入口仅接受 `modelId`，未证明可传不可变 revision 或本地目录，且缓存元数据失败时可能回退到联网下载。因此 Qwen 的离线、本地、固定 revision 加载仍未完成验收，是 smoke 必须验证的能力，不得由清单状态推定已经解决。

## 3. 语料合同

正式验收语料至少 100 条，每段音频只录一次，所有候选读取同一份不可变文件。调参和 Adapter 开发集必须额外建立，不得计入这 100 条或正式得分：

| 分类 | 数量 |
| --- | ---: |
| 普通中文短句 | 40 |
| 中英混说 | 15 |
| 姓名、公司、产品和专业术语 | 15 |
| 数字、金额、日期、时间和版本号 | 10 |
| 改口、重复和填充词 | 10 |
| 列表或步骤 | 5 |
| 30–60 秒长语音 | 5 |

正式录制前先让三套候选各自运行同一批 10 条非正式小样，验证下载、加载、输入格式、转录、三种计时和汇总链路。三者可独立推进；小样不得计入最终得分。固定文字的网易 UU 粘贴与剪贴板恢复验证不依赖 ASR，可与小样并行开展。

至少 100 条验收语料整体冻结，只运行在额外开发集上确定的配置，不得据验收结果回调参数。类别计数是内容维度；时长分组是独立维度，不要求每个内容类别机械均分。

每条记录写入 `benchmark/corpus/manifest.jsonl`：

```json
{"sample_id":"S0001","audio_path":"audio/S0001.wav","audio_sha256":"lowercase-hex","reference_text":"人工核对原文","category":"zh_short","environment":"quiet","duration_ms":10000,"notes":[]}
```

约束：

- `sample_id` 不包含姓名等个人信息；
- 私人音频默认不提交 Git，仓库只保存脱敏清单模板；
- 原始音频一经冻结不得按模型分别剪辑；
- canonical corpus 固定为 16kHz 单声道 PCM/WAV，记录转换参数与文件 SHA-256；所有候选从这份相同输入开始；
- 若 Adapter 因实际引擎能力需要其他采样率，必须显式重采样，并记录输入/输出采样率、产物 SHA-256 与 `resample_ms`。Qwen smoke 修订前的 24kHz 是旧实现；按固定上游源码核实默认值后，CLI 已改用 16kHz，旧值不构成引擎要求；
- 办公室噪声版本属于额外样本或明确配对样本，不得悄悄替换安静样本。
- 语料按短（≤10 秒）、中（>10 且 <30 秒）、长（30–60 秒）分组报告；
- 验收集须提前冻结至少 30 条 9–11 秒固定子集，专门用于“10 秒语音”P50/P95；
- 另建不计 CER 的负样本集，至少包含静音、纯噪声、近空音频和损坏/不支持格式，检查空结果、幻觉文本及可追溯失败。

## 4. Adapter 输入输出

每个引擎 Adapter 接受同一 `sample_id` 和音频文件，输出一行 JSONL：

```json
{
  "run_id": "immutable-run-id",
  "sample_id": "S0001",
  "engine": "candidate-name",
  "engine_version": "exact-version",
  "model_revision": "immutable-revision",
  "device_profile": "profile-id",
  "language": "zh",
  "raw_text": "识别原文",
  "load_ms": 0,
  "cold_transcribe_ms": 0,
  "warm_transcribe_ms": 0,
  "resample_ms": 0,
  "peak_rss_bytes": 0,
  "success": true,
  "error_code": null
}
```

共同约束：

- 任务固定为 transcription，不执行翻译；
- 明确使用中文 `zh`；若某引擎不支持该参数，Adapter 必须记录能力差异；
- 基线轮不使用用户词典、LLM、OpenCC 或模型专属后处理；
- 词典增强轮只能使用完全相同的词表，并与基线结果分开统计；
- 不允许只为某个模型删除困难样本或调整参考文本；
- 运行失败保留结果行，不得静默重试后覆盖失败证据。
- 每个候选必须实际打包并运行于最小独立进程 Worker，验证模型加载、请求/结果序列化、取消、进程断连、主进程失联检测、Worker 重启和模型文件格式；再按三个实际依赖能提供的能力冻结共同 XPC 协议。仅做进程内调用不足以通过该闸门，暂未验证的字段必须明确标记。

## 5. 文本评测口径

同时保存并报告两套指标：

1. `raw_text`：引擎原始输出，用于检查繁体、标点、重复和异常内容；
2. `content_normalized`：仅用于内容准确率比较。

`content_normalized` 的固定顺序：

1. Unicode NFC；
2. OpenCC 转大陆简体；
3. 拉丁字母转小写；
4. 合并 Unicode 空白；
5. 去除标点和比较无意义的空白。

不得使用 LLM、词义改写、同义词替换或人工纠错参与归一化。

主要准确率指标：

- 中文内容 CER：归一化后的 Levenshtein 字符距离除以参考文本字符数；
- 术语准确率：预先标注术语的完全匹配数除以术语总数；
- 数字完整率：预先标注的数字、金额、日期、时间和版本号完全保留比例；
- 空结果率、重复片段率和整句遗漏率。

此外单独报告保留标点和空格的 display CER，但不用于选择主模型，避免把标点风格与内容识别混为一谈。

## 6. 时间与资源口径

- `load_ms`：进程开始加载模型到 Adapter 报告 ready；
- `cold_transcribe_ms`：模型 ready 后第一次完整转录；
- `warm_transcribe_ms`：预热完成后，从提交完整音频到最终文本返回；
- `resample_ms`：从 canonical 16kHz 输入转换到 Adapter 实际输入格式的时间，独立报告，不得混入模型转录时间；
- 不把音频录制时间、OpenCC、润色、焦点恢复或粘贴时间计入 ASR 时延；
- 每个候选至少完成 1 个全新进程冷轮，再完成 1 次不计分预热和 3 个热计分轮；冷轮与热轮分开报告；
- 每轮样本顺序使用已保存的随机种子打乱；
- P50/P95 从全部成功的计分轮计算，失败率另报，不得排除慢速成功样本；
- 重复轮按 `sample_id` 保留层级并报告样本内波动；同一批 30 条固定音频运行 3 轮仍是 30 个独立样本，不得表述为 90 个独立样本；
- `peak_rss_bytes` 使用同一种系统采集方法；磁盘占用按模型清单文件实际字节数计算；
- 温度、电源方式和其他高负载进程必须记录到 run metadata。
- P50/P95 除总体值外，必须按短、中、长三个时长组分别报告。

正式选型必须在 Apple M5、16GB MacBook Air 上执行。任何其他机器的结果只能标记为开发机数据；旧文档中的 M4/32GB Mac mini 是历史环境，不能代表当前本机。

## 7. 硬门槛

候选必须同时满足：

| 指标 | 硬门槛 |
| --- | ---: |
| 清晰语音中文内容 CER | ≤ 8% |
| 姓名/术语准确率 | ≥ 95% |
| 10 秒语音 warm ASR P50 | ≤ 0.8 秒 |
| 10 秒语音 warm ASR P95 | ≤ 1.8 秒 |
| 100 条连续识别 | 无崩溃、死锁、音频尾部丢失 |

数字完整率必须完整报告；“100% 才允许智能润色上线”属于后续产品闸门，不在本阶段被误写为 ASR 候选淘汰规则。

## 8. 选型规则

三套候选先应用完全相同的硬门槛。通过者依据内容 CER、术语与数字准确率、三种时延及其时长组分布、冷热轮稳定性、失败/异常率、资源占用和集成依赖的实际差异作出 ADR。若差异落在测量波动内，优先选择跨轮更稳定、失败更少且依赖更简单的候选，并在 ADR 中保留不确定性。

本版不计算综合分，只保留原始指标、置信区间/波动说明和 ADR 判断。以后如需综合分，必须先修订合同并在查看对应正式结果前冻结绝对映射公式，不能事后补公式或使用候选间相对归一化。

## 9. 证据包

阶段完成时必须保留：

- 环境与设备 profile；
- 模型清单及 SHA-256；
- 脱敏语料清单和音频 SHA-256；
- 每次运行的原始 JSONL；
- 汇总 CSV/Markdown；
- 失败日志，且不得包含完整私人转录；
- 可复现命令；
- 模型选型 ADR，或 `NO_MODEL_SELECTED` 结论。

## 10. 当前执行顺序

1. 当前 Xcode Beta 27.0（27A5252f）与 Metal Toolchain 已验证可用；App Core 5 项、Qwen Core 4 项测试通过。使用命令级 `DEVELOPER_DIR=/Applications/Xcode-beta.app/Contents/Developer`，未改全局设置；
2. 三候选下载前元数据已齐备；Qwen 6 个文件下载后大小/SHA-256 已核验，并完成 `SMOKE-001` 的 Debug 转录和输出通道修复复跑。其他候选、本地不可变入口、严格离线与正式冷热基准仍未验收；详见 `docs/阶段0-环境恢复与Qwen冒烟-2026-09-08.md`；
3. 三套候选各自用同一批 10 条小样验证下载、逐文件校验、加载、输入格式、转录、计时和汇总；固定文字 UU 粘贴验证可独立并行；
4. 在 Xcode 与所需工具链就绪后，将各候选实际打包到最小独立进程，试验加载、序列化、取消、断连检测、重启和模型格式，证据充分后冻结统一 Adapter/Worker 协议；
5. 用临时候选完成基础闭环实测，不把它表述为正式模型选型；
6. 使用额外开发集完成调参后，冻结含时长组、至少 30 条 9–11 秒固定子集和负样本的至少 100 条正式验收语料并运行盲测；
7. 基于硬门槛、原始指标差异和稳定性生成选型 ADR；本版不计算综合分。
