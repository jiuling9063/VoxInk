状态：三个候选均通过本轮最小独立进程验证。不是产品 XPC 服务验收，也不改变默认模型未选定的状态。

每个候选覆盖启动取消、推理阶段取消、取消后的完整识别、推理阶段 SIGKILL、崩溃后的完整识别、推理中 stdin EOF。两个完整识别均返回非空文本并通过模型缓存前后校验。取消耗时从控制端发出请求到收到确认，单次观察，不是 P95 或产品响应承诺。

网络策略为 `(version 1)(allow default)(deny network*)`。无沙盒时可绑定本地端口，同一程序在沙盒内得到 EPERM；所有模型子进程都在该策略下运行。没有修改系统 Wi-Fi、代理或防火墙。Core ML / ANE 系统服务仍可工作。本结论适用于已准备好的当前模型、分词器缓存及本机环境，不是上游代码已删除联网回退的证明。

## 本次实现

- 新增 `script/asr_worker.py`：串行 JSONL 控制协议、一次一个活动请求、请求 ID 防重复、超时、进程退出与取消清理。
- 新增 `script/check_asr_worker_live.py`：网络策略对照、三个真实模型生命周期测试与证据保存。
- 新增 `script/tests/test_asr_worker.py`：7 项真实子进程测试，覆盖取消后恢复、推理标记与迟到结果、崩溃恢复、父端 EOF、超时、忙碌/重复请求、非法 JSON；全部 Python 测试合计 21 项通过。
- 两个 Swift 入口新增由 VOXINK_WORKER_PHASES=1 启用的推理开始诊断标记，不包含音频或转录正文，默认单条和批量入口保持原输出协议。两个 Release 构建通过。

## 发现与最小修复

最初通过 Python Whisper 适配脚本再启动 Swift，推理取消时进程组退出路径出现 PermissionError / EPERM。改为控制层直接启动 Swift，保留控制层已有的模型和分词器校验，三个候选统一为直接模型子进程。修复后重跑全套实测通过；未把早期失败结果覆盖。这里只确认调用层级简化后问题消失，没有对 macOS 内部信号实现作未经证实的归因。

## 证据与下一步

有效证据：`benchmark/results/worker-direct-offline-20260908/summary.json`、各候选 `events.json` 和任务日志；二进制、脚本与清单哈希已保存。早期启动阶段结果在 `worker-offline-20260908`，失败诊断在 `worker-inference-offline-20260908` 和 `worker-cancel-diagnosis-20260908`，都只是历史证据。

本层每次请求重新加载模型，取消采用终止进程，适合作为故障隔离基线。下一步实现常驻模型 Worker，将 ready、请求 ID、终态、取消与连接生命周期接入 Swift 主进程；控制层自身被 SIGKILL 时的孤儿回收尚未验证。正式产品 XPC、签名权限、100 次稳定性、准确率和 UU 自动粘贴仍未验收。
