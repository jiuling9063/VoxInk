# 阶段 0：最小 App 联调（2026-09-08）

## 范围

新增 SwiftUI 原生窗口和菜单栏，复用常驻 Worker 客户端。录音层使用 AVFoundation，点击后才请求麦克风权限；录音最长 60 秒，停止后整段识别。导入音频会生成私有临时 WAV，不改动原文件。Qwen 只作为临时集成候选。

## 已观察到的界面行为

- 通过 `.app` 启动，窗口可见，自动校验模型后显示“本地模型已加载”。
- 从文件选择器导入 `SMOKE-001.wav`，显示非空转录与“识别完成”。
- 从桌面导入 `VoxInk-test.m4a`，系统解码、归一化和同一常驻 Worker 识别成功。
- 点击复制后显示“已复制”；未向任何聊天对象发送内容。
- 两次导入后临时音频目录为空。正常退出后 App 与 Worker 均退出。
- 最终版本在音频工作文件出现后接受 SIGTERM：App 和 Worker 均退出，观察耗时 120ms，临时目录为 0。随后冷启动和签名检查通过。证据：`benchmark/results/gui-smoke-20260908/active-audio-exit-fixed.json`；初次失败保留在同目录 `active-audio-exit.json`。

自动化检查：App Core 20 项、UI 状态 4 项，共 24 项通过；脚本语法、系统 Bash 3.2 空 PID 列表和本机打包构建通过。GUI 观察及最终源码/二进制哈希记录在 `benchmark/results/gui-smoke-20260908/summary.json`，不包含转录正文。

这些检查证明界面导入闭环，不代表准确率、真实麦克风、快捷键或远程粘贴验收通过。麦克风权限、真实电平与 60 秒硬件停止未自动操作。

## 修复的问题

1. WAV 转换器输出 Int16，而 `AVAudioFile` 默认写入处理格式为 Float32，导致测试进程断言退出。显式统一处理格式，并排空转换器尾帧；测试校验 0.25 秒输出约 4000 帧。
2. 取消导入时没有等待异步转换结束，立即退出可能遗留文件。取消现在等待音频操作与清理完成；迟到结果不能恢复旧会话，重复取消等待同一清理任务。
3. Run 重启的 SIGTERM 原本绕过 AppKit 退出清理。改接 AppKit 后，实机又发现从主线程 dispatch 回调直接进入 `terminateLater` 会阻塞清理任务。信号现在排程到下一次 RunLoop 再触发正常退出，脚本等候退出，超时中止构建。
4. 同步目录会给真实 App 附加导致签名拒绝的属性。实际产物改放用户缓存，`dist/VoxInk.app` 作为链接；脚本验证签名后再启动。

## 使用与边界

启动入口、模型缓存前提与验证命令见 [最小 App 使用与验证](最小App使用与验证.md)。当前无音频上传、无转录日志、无自动粘贴，结果仅保留在当前进程内。异常强杀或系统崩溃的遗留音频清扫仍未产品化；正常取消和退出使用本轮清理链路。
