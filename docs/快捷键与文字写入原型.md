# 快捷键与文字写入原型

## 操作

- 默认切换到目标输入框，按住 `Option + Space` 录音，松开后停止、识别并写入；无需第二次按键。最长仍为 60 秒。
- 窗口的“快捷键模式”可切换为“按一次开始，再按结束”，选择会保存在本机；活动会话期间不可切换。短于 0.2 秒或麦克风尚未准备好就松开的录音取消，不写入文字。
- 浮层显示录音/识别状态，不激活窗口，不主动抢走输入焦点。
- 活动快捷键会话中按 `Esc` 取消。发出粘贴前可阻止输入；发出后无法撤回，仍等待本地剪贴板清理。
- 识别后按 PID 与 Bundle ID 确认目标应用，恢复焦点并只发出一次 `Command + V`。显示“已发送粘贴”只代表本机按键已发出，不能证明远端已收到。
- 窗口里的“开始录音”和“导入音频”保持预览行为，不自动写入。失败后结果保留，可复制；已有目标的结果可显式点击“重新粘贴”，这会建立新的事务。

## 权限与验证

全局快捷键采用 Carbon hotkey 注册，不监听所有键盘内容。文字写入需要 macOS Accessibility 权限，点击“允许文字写入”后由用户在系统设置允许。当前本机 macOS 27 界面路径为“隐私与安全 → 设备控制和数据访问”，列表条目名为 `VoxInk`；旧系统称“辅助功能”。权限未允许时，不修改剪贴板、不发出按键。

本机开发包使用临时签名；本轮实测重编译后系统不沿用旧二进制的授权，需要刷新现有 VoxInk 条目。先完成最终构建再授权，后续正式分发需稳定开发者签名。原型窗口若底部入口被挤出，可先放大窗口。

展开窗口中的“原型验证”，点击“准备固定文字测试”，再切换到目标输入框按 `Option + Space`。这一次只写入固定测试文本，不打开麦克风；测试模式使用一次后关闭。

排查快捷键与粘贴链路时，可点击“3 秒后测试写入”，立即切换到目标输入框。倒计时结束后才捕获目标，执行同一固定文字写入流程，不需要按快捷键，也不启用麦克风；倒计时期间可点击“取消”。

本地隔离测试框：

```bash
./script/run_paste_fixture.sh
```

该窗口计数收到的粘贴动作，不连接任何聊天应用，也没有发送功能。用于先验证固定文字、单次触发和恢复目标。UU 远程微信需继续在“文件传输助手”的空白输入框测试，不按发送。

2026-09-08 排查：测试框已补齐标准编辑菜单，并显示本窗口收到的按键编号及 Command/Option 标志，不记录键入内容。CUA 直接 Command+V 已使固定文字出现且计数为 1，证明接收端可工作；用户物理快捷键测试仍未观察到自动插入，期间主程序曾显示“已发送粘贴”，随后又进入音频识别失败状态，后续触发原因未确认。新增延迟验证入口后，重建包遇到旧签名权限失效；用户完成触控 ID 解锁后，移除旧 VoxInk 条目并添加当前包，应用确认授权生效。随后“3 秒后测试写入”实测成功：固定文字出现、粘贴计数 1、收到 keyCode 9 且 Command=true / Option=false、完整剪贴板恢复通过；显式重新粘贴后计数 2 且恢复仍通过。以上证明按钮触发的本地自动粘贴链路通过，物理快捷键与 UU 远程路径仍待单独验证。自动测试共 49 项通过（Core 36、UI 13）。

## 剪贴板边界

粘贴前复制所有项目/类型的数据，并检查版本号。写入后等待修饰键释放，重新确认焦点、权限和剪贴板所有权，再发出一次粘贴。恢复窗口暂定 1.2 秒；仅当前版本仍属于本事务才恢复原快照。期间用户复制新内容时保留新内容，不自动重试粘贴。

原型只记录目标应用身份，不能识别 UU 内部的远程窗口或密码框，也不能确认远端接收。正式版本仍需要更全面的目标窗口策略、异常场景测试及 50 次 UU 验证。

2026-09-08 后续物理快捷键实测：用户按一次 Option+Space 后，测试框出现准确固定文字，粘贴计数由 2 增至 3，完整剪贴板恢复通过；收到 keyCode 9、Command=true、Option=false，App 显示已发送粘贴且固定测试模式退出。此单次本地快捷键→固定文字→自动粘贴链路通过。真实录音后自动写入、UU 远程输入与重复稳定性测试仍待验证，之前空白测试的具体原因未完全复现，不能归结为单一原因。

2026-09-08 真实语音闭环验收：用户按前述本地测试流程完成快捷键开始录音、再次按键停止、识别并自动写入，反馈“测试通过，文字识别准确”。本次结果依据用户人工确认；未保存其语音或转录文本，不外推为整体准确率。当前本地功能原型闭环通过，下一项为 UU 远程固定文字及真实语音写入验证，重复稳定性与正式语料评测仍待完成。

## 2026-09-09 简体与按住模式更新

早期 App 曾开启 `--simplified-output`，通过 context 引导模型输出简体；2026-09-09 长录音验证发现静音时会回显整段提示语，App 现已停用该参数，使用无提示 ASR 加本地 OpenCC 输出简体。CLI 仍保留该实验参数用于复现，带提示的旧结果标记 `output_policy=simplified_prompt_v1`，不能混入当前 App 性能结果。

原始转录保留在内存，最终显示、复制和自动粘贴统一经过 OpenCCSwift `full twp → cn`（固定提交 `69fdd9601a7bee4485ea60847910e40744608012`）。此配置已用大陆常用词和字形样例验证。数字、URL、邮箱、路径、英文标识符、反引号代码及代码围栏按原始区间复制，保护内容可以保留繁体。转换器启动时构造并复用，只有 OpenCC 不可用才使用系统字符级降级并在界面提示；两者都不可用时保留原文并提示。当前未新增润色、词典或其他格式改写。

验证：App 64 项测试、Qwen Worker 7 项测试通过；3 段已有录音在禁网 Worker 中带简体提示转录成功，本轮观察均为简体，不代表整体识别准确率。修复启动不显示窗口后，已验证主窗口显示和关闭后恢复、模式切换、GUI 导入 SMOKE-003 显示简体结果；旧签名权限记录刷新后 App 确认文字写入授权生效。实体键盘按住松开手势、单次粘贴和新版 UU 简体输出仍待现场完成；旧版切换式远程识别内容准确但繁体，是本轮修改的触发原因。

后续用户反馈“测试成功”，按本轮说明确认了实体按住/松开、单次简体写入。测试输入框未再次指定，未记录其音频或转录内容。新增 6 项稳定性回归后 App 共 70 项通过，包含 50 次交替模式的模拟会话、60 秒自动停止边界、麦克风权限拒绝后恢复、识别失败后恢复、取消后的迟到结果、粘贴失败后显式重试。模拟录音时长与粘贴调用不替代真实 60 秒收音或 50 次 UU 验收。

静音修复后 App 共 74 项测试通过。整段采样全为零（或无采样）时，不调用 ASR、不发出粘贴，保留上次文字并提示重新录音；存在任何非零信号均继续识别，不设置响度阈值。本规则不是 VAD，不能保证所有环境噪声都不会产生误识别。修复版 GUI 已验证 60 秒纯静音被拦截、正常中英音频识别成功；新版真实录音与写入需在系统授权恢复后继续验证。
