## 安装与恢复流程

启动只检查并复用本机已有模型。新目录缺文件且旧开发缓存也不可复用时，界面提示“下载或继续安装”；只有用户选择安装后才允许网络下载。下载器只接受 App 中固定清单的 HTTPS revision 地址，音频不交给下载器。

每个文件先写入私有 `.partial` 目录。中断或取消保留已经写入的部分，下一次请求发送 HTTP Range；服务器返回完整 200 响应时从头重写临时文件。响应类型、范围、大小和最终 SHA-256 都接受检查。完整但错误的临时文件不会继续追加，也不会替换现有模型；再次操作重新下载该文件。

只有校验通过的文件才原子替换正式文件。安装器拒绝非预期目录链接、链接临时文件、硬链接临时文件和清单外权重。进程内状态和文件锁共同避免同目录并发安装；取消会等待安装操作退出并释放文件锁。新生成目录为 0700，临时文件为 0600，模型根目录排除备份。

## 发现并修复的问题

1. 目录检查递归到文件系统根目录时未正确结束，测试进程发生栈溢出。改为有限的路径组件遍历，并增加根目录测试。
2. macOS 的 Foundation 路径处理仍可能保留 `/var` 别名。测试临时根目录改为用 `realpath` 取得真实路径；产品安装器继续检查目录组件，不放宽链接保护。
3. 极小 URLProtocol 数据块会被 Foundation 缓冲。断流测试改用 100KB 数据及 40KB 断点，确认收到并写入数据后再验证取消/继续；未通过固定睡眠假定文件已经写入。
4. 仅复制六个模型文件不足以满足固定上游 Hub 的离线快照规则。核对 `speech-swift` 与 `swift-transformers` 固定源码后，安装器为已校验文件生成本地缓存记录：固定 revision、真实 SHA-256 内容标识与校验时间。该格式允许 Hub 重新计算 SHA-256 校验文件，不是伪造服务器 ETag，也不依赖在线缓存刷新。修复后真实禁网加载通过。

## 验证命令

在项目根目录执行：

```bash
DEVELOPER_DIR=/Applications/Xcode-beta.app/Contents/Developer swift test --package-path app --scratch-path /tmp/voxink-app-xcode-beta
bash script/check_model_contract.sh
DEVELOPER_DIR=/Applications/Xcode-beta.app/Contents/Developer swift run --package-path app --scratch-path /tmp/voxink-app-xcode-beta voxink-model-check --manifest benchmark/model-manifest.json --download-small-file
./script/build_and_run.sh --verify
```

`voxink-model-check` 默认安装检查只复用本地缓存；`--download-small-file` 额外下载清单中最小且不超过 100KB 的文件，验证实际地址和哈希，然后删除该检查临时文件。它不是整套冷下载验收命令。

证据目录：`benchmark/results/model-install-20260909/`，包含当前测试日志、真实下载/迁移结果、禁网 Worker 加载记录与 `summary.json`。本轮 App SHA-256：`4b5707d367d2b7dd709d74c960264c0c61f624de12828805a199df0f52f80d6c`。
