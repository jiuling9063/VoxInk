## HUD 的共同材质

前几版 HUD 使用深色底、亮色波形，与 Logo 浅色玻璃底板关联不足。本轮统一四个要素：浅冰青色的透底、细亮边、局部青色折射光，以及很短的投影。

- 保持常态约 288 × 56，状态文字 13 px、辅助文字 11 px，不通过缩字减重。
- 玻璃背景层默认不透明度 42%，即透明度 58%；演示可调 40%–68% 透明度。
- 文字始终不透明。文字区域保留 64% 局部底层并向边缘渐隐，因此背景透明度不等于整块 HUD 的合成透明度。
- 浅色、青色桌面采用深青文字；深色桌面保持冰青反光，改用浅色文字与局部深色底层。
- 模糊降至 14 px，让底部环境色更容易透出；底缘光仍为 1 px，动态只作用于波形和边缘光，文字底层不随声量明暗变化。
- 减少动态时移除追随光与动态效果；减少透明度或不支持模糊时使用实底回退。

Logo 放在 HUD 旁边只是提案页的材质对照，不会在正式录音浮层旁常驻显示 Logo。主窗口沿用 v3 的有序分组。

暗背景适配在演示中由“桌面背景”控件切换，不代表实现了任意真实桌面的自动采样。原生版需要结合系统外观和实际材质验证对比度，不能直接把 CSS 参数当作已验收的原生材质。

## 交付与验证

### 完成边缘反馈

用户认可目前 HUD，并提出完成时四周光效，要求功能和资源优先。采用一次 700 ms 的整圈冰青柔光：淡入后淡出，背景、文字、轮廓和模糊半径不随动效改变。只对边缘层透明度做动画，不添加循环计时器、粒子或持续旋转。完成文字仍停留约 1.5 s，光效不延迟业务流程，也不延长既有演示收起时间。

只在 `done`（演示含义为已发出粘贴）进入时播放，取消和失败不播放成功光效；重试成功可播放一次。减少动态时改为静态亮边，保留完成文字。光效表达当前粘贴操作已发出，不能表达远端必然收到。

原生实现注意：目前 `RecordingFeedbackPresentation` 的 `.ready` 本身不足以区分成功、取消和其他回到就绪的情况。应读取本次实际写入结果，并按会话标识确保仅触发一次，不能监听 `.ready` 就播放。动画不进入音频/识别/写入关键路径；不得为了光效改变当前浮层不激活、不抢焦点的行为。

资源占用尚未实测，不能承诺零开销。原生阶段对开启/关闭动效做响应、CPU/GPU、内存和隐藏后空闲状态的对照；如出现响应退化或隐藏后仍绘制，优先退回静态亮边。连续录音光效仍属于独立设计项，本轮仅限定完成光效。
